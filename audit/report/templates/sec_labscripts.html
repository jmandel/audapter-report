We read the lab's public experiment scripts and found three things, of different weight. One is a real open question: as committed, the public vsaGeneralize runner, which its public experiment script calls, perturbs the baseline trials and never scales the field (LAB-2); the lab's logs can settle it, and the later vsaGeneralize2 study is wired correctly. One is repository hygiene: vsaCentralize's repository ships an unused runner with wrong field wiring, while the runner its experiment calls is correct (LAB-1). One is a known, harmless dead setting: p.fb4Gain never reaches Audapter, as the lab's own code already notes, so every fb 4 study used the same default level (LAB-3). Every parameter sequence was reproduced exactly, with the lab's own calc_pertField, through Audapter. This is a reading of public code, not a claim about published results.

For reference, vsaSentence is wired as designed: it sends the mel grids after init (run_vsaSentence_audapter.m lines 67–71 @c01942f), and at strength 0.5 every vowel is heard [[vsaSentence_tc_min:.2f]]–[[vsaSentence_tc_max:.2f]] of the way to the centre (intended 0.50). That wiring, also used by the runner vsaCentralize's experiment calls, is the "Expected" in LAB-1 and LAB-2.
