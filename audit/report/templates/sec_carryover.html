Carrie Niziolek asked whether, in designs where perturbed trials are followed by unperturbed ones, one trial's lingering state can affect the next. As blab runs its experiments, it does not. With other OST rules or other ways of switching conditions, it can, and the effect is large and silent. This section shows both.

blab's switching methods: no carry-over

We ran each method the lab uses to change the condition between trials, with the lab's own settings and OST files, in mixed sessions of perturbed and catch trials, once in order and once in reverse order.

Across all 69 OST files in blab's public and unpublished experiment code, every one of the 57 INTENSITY_FALL rules comes after a rule in the same trial that refreshes the stored time, so none can read the previous trial's value (blab's timeWrap uses the RMS-floor rule for a burst onset, but a rise-and-hold rule runs before its FALL). No blab OST has a maxIOI timeout. The one remaining difference between trials is cosmetic: the first trial after MATLAB starts logs slightly different formants for its first 36 ms of voicing (the tracker's memory; the audio is identical). Evidence: exp_mixed.m (S1, S2), exp_simon_session.m; log entries EXP-2, EXP-6, EXP-10.

What to avoid: when carry-over does happen

OST-F1 · offset detected later every trial

Affected if an INTENSITY_FALL rule has no refreshing rule before it in the same trial: the only rules before it are ELAPSED_TIME, the RMS-floor rule (…_WITH_RMS_FLOOR, mode 32) or the ratio rules (INTENSITY_RATIO_RISE, INTENSITY_RATIO_FALL_HOLD). These do not refresh the stored time; every other rule does. Reloading the OST or re-running init does not help.

Safe if any rise-and-hold, slope, stretch, FALL or AND_RATIO rule runs before the FALL in the same trial, as in every blab OST.

COORD-1 · a PCF left loaded from an earlier block

Affected if a field-mode block follows any block that loaded an OST/PCF (every blab session starts with the measureFormants calibration) and does not clear them. AudapterIO('init') does not.

Safe if the runner calls Audapter('ost', '', 0); Audapter('pcf', '', 0); first, as every blab field-mode runner does.

OST-F5 · pitch catch trials shifted

Affected if pitch catch trials are made with Audapter('pcf', '', 0) after a trial that ended while shifted, without re-running init.

Safe if catch trials load an all-zero PCF, or init runs before every trial.

OST-F2 · maxIOI timeout drifts

Affected if the OST has a maxIOI (timeout) section and is loaded once for many trials.

Safe if there is no maxIOI section (all blab OSTs), or the OST is reloaded before every trial.
