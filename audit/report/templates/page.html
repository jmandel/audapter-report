What we looked at

Audapter shifts a speaker's formants or pitch, or plays masking noise, in real time for altered-auditory-feedback experiments. We examined the blab-lab version, its C++ core and MATLAB code, and asked: does it do what experimenters think it does, trial after trial?

How

  • We ran the real code without MATLAB or audio hardware, fed it synthetic voices and 80 real voice recordings, and measured what came out (method).
  • We checked for memory errors with standard sanitizers, and simulated the live sound-card path, including its two threads.
  • We proved a few pieces of logic correct or incorrect for all settings.
  • A browser build lets you rerun several findings on this page, with and without a fix.

Methods

Running the real code without MATLAB or audio hardware

The C++ core is compiled as a MEX file for GNU Octave, which implements MATLAB's MEX interface, and driven through the lab's own MATLAB code (getAudapterDefaultParams.m, AudapterIO.m), unmodified. Audio goes in frame by frame through Audapter('runFrame'), which runs the same processing function as the live audio callback. We then read back what Audapter logged and measured the output audio independently: formants with our own LPC, F0 by autocorrelation, and level in 20 ms blocks. The only source changes are two portability edits, one of which makes GCC behave like the Windows compiler. A second build with AddressSanitizer and UBSan reports out-of-bounds memory access at the exact line.

Checks on the test setup

  • Repeated identical trials give bit-identical output, and the tracker agrees with an independent LPC within 5 % on four vowels.
  • An apparent 25 % overshoot of F1 shifts at F0 200 Hz was a bias of our LPC measurement: vowels synthesised at the target formant show the same bias. Formant checks use F0 120 Hz.
  • We ran the original Audapter 2.1.5 through the same harness, on synthetic input and on the real recordings. Output and logged data matched bit for bit, except for the field re-entry rule in F6.
  • The WebAssembly build matches a native build with the same maths library bit for bit, and the MATLAB-compiled build within 3·10−11.

Real speech

Every main finding was repeated on 80 openly licensed recordings (197 s): adult men and women, children aged 6–7, singers, voices with dysphonia, speech in real background noise, and three session recordings shipped with Audapter. A script re-fetches each original from pinned sources and rebuilds the set byte for byte. On these recordings the formant tracker's median error against the hand-corrected measurements of Hillenbrand et al. (1995) is 1.3–2.0 %; formant shifts are logged exactly and measured in the output within 2–3 % of the command; the old sessions replay within 0.2–0.4 % of what was logged online; and the sanitizers found nothing new in 480 clip-scenarios. No voice in the set is above about 350 Hz F0, so high voices are untested.

The live audio path

To test the path used in experiments, the real audio code (audioIO.cpp and RtAudio with its ASIO backend) was built with Audapter and driven by a simulated ASIO driver that calls back at real period boundaries, and cross-checked against a JACK server. Live processing matches offline processing bit for bit, with two buffers of delay, so the offline cards apply to real sessions. The usual reset–start–stop–getData flow per trial showed no data races in 300 runs under ThreadSanitizer. The driver is modelled and the build is GCC on Linux, so crash and click rates are indicative, not Windows figures.

Proofs

For a few pieces of logic we asked for which settings a bug occurs and whether the fix works for all settings. CBMC, a model checker for C, runs on the verbatim, hash-pinned buffer-index code and was checked for every frame length Audapter accepts (1–120) and six common larger ones, with no failures. It gives the exact conditions for the delay-buffer and recorder overruns and proves their fixes. Lean 4 proves, on a line-by-line model of the OST state machine, that with the OST-F1 and OST-F2 fixes no trial depends on earlier trials, and that neither fix alone suffices; the proof is about the model, not the compiled code. Exact algebra gives the phase vocoder's 3/2 gain (PT-5) for every hop ratio of 3 or more. The whole signal-processing chain was not model-checked.

Running Audapter in the browser

Panels on several cards run the real C++ core, compiled to WebAssembly from the same commit, on the card's inputs, with and without a small patch. Each patch is bit-identical to the current code on reference scenarios it should not affect and removes the finding's effect (audit/report/wasm/check-patches.mjs). Panels load on click, work offline, and use 150–300 MB of memory per run; on a phone, run one panel at a time.

Who did this, and reproducing it

The audit was carried out by Claude, an AI model made by Anthropic, with AI sub-agents, at the request of Josh Mandel, who commissioned it and decided what to publish. Nothing here needs to be taken on trust: every finding links the code at a pinned commit and gives a reproduce command. The whole pipeline was rebuilt from a fresh clone; of the 17 full cards the report then had, 13 rebuilt byte-identical, and the other 4 measure quantities that vary by nature (a click's size, crash counts, time to a hang, memory contents). Requires Docker: ./reproduce.sh at the repository root rebuilds everything.

Level and loudness

Every card states level changes as RMS level in dB, measured on the output audio: exact, and what a lab can check in signalOut, but physical. How loud a change sounds also depends on the spectrum (equal-loudness contours are not flat) and on the presentation level, so where a card compares levels we add a perceptual estimate as a secondary, model-based range: ISO 532-1 time-varying loudness (Zwicker; mosqito 1.2.1, free field), statistic N5 (loudness exceeded 5 % of the time), converted to loudness level in phons and to the equivalent level change (the gain on the expected clip that gives the observed loudness), with ECMA-418-2 (Sottek) as a second model for the spread. The expected clip is presented at 60, 70, 80 and 85 dB SPL (A-weighted), the observed clip at the same gain; we assume diotic headphones with a flat response and a normal-hearing listener. The trade-off: the level is exact but physical, the loudness estimate is perceptual but rests on these assumptions; older or clinical listeners and real headphones may differ. For "noticeable" we use a level change of about 1 dB, the order of the intensity just-noticeable difference for broadband sounds such as speech and noise at moderate levels (Miller 1947, J. Acoust. Soc. Am. 19:609). Sanity check (equal RMS, +2 semitones, 70 dB SPL): a harmonic complex at 120 Hz gains [[LS_hc120_dphon:+.1f]] phon in ISO 532-1, the direction the equal-loudness contours predict; for pure tones (150 Hz, 1 kHz) the two models disagree in sign by under 1.2 phon, so differences below about 1 phon on tones are within the models' resolution. The broadband effects on the cards, 1 dB and more, agree in direction across both models; ECMA-418-2 gives about half to two thirds of the ISO 532-1 magnitude.

Limitations

  • Octave, not MATLAB; GCC on Linux, not MSVC on Windows. Out-of-bounds reads can return different values on Windows.
  • The live path is simulated with a modelled ASIO driver.
  • Recordings, not a live talker hearing the feedback; no voices above about 350 Hz F0.
  • Severity is our judgement of experimental impact.
